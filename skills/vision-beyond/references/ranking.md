# 价值排序

## 先过门槛

候选必须能回答：发生了什么变化、为什么与用户有关、用户下一步是什么。无法回答时直接丢弃。

## 内部评分

| 信号 | 分值 |
|---|---:|
| 明确待用户处理的审批 | +28 |
| 明确 `@` 用户且形成回复期待 | +25 |
| 私聊请求、问题或确认 | +20 |
| 命中已确认工作议题 | +20 |
| 决策、阻塞、风险或状态变化 | +18 |
| 负责人、截止时间或交付物变化 | +15 |
| 两类以上来源相互印证 | +15 |
| 相关文档在窗口内新建、多人阅读且未发现本人访问证据 | +18 |
| 用户未参会且出现相关新结论 | +12 |
| 相关文档在用户上次打开后更新 | +15 |
| 仍未闭环且超过一个工作日 | +8 |
| 消息 reaction 数量明显高于同批候选 | +1 至 +3 |
| 寒暄、纯转发、重复通知 | -20 |
| 无责任、无行动、无议题关系 | -20 |
| 只有 AI 摘要，缺少原始证据 | -12 |

时间衰减只作用于低价值背景项；仍有效的审批、风险、截止日期和未闭环请求不因变旧自动消失。

文档阅读量与消息 reaction 加分分别封顶。热度只能辅助排序，不能替代工作地图相关性、变化和行动价值。当前用户发过 reaction 只说明接触过消息，不能直接判定请求已经闭环。

## 置信度上限

- 阅读状态未知、线程不完整、文档打开字段缺失：最高中置信度。
- 只有发送者身份或消息热度：低置信度并降级。
- 同一事实已被用户回复、确认或处理：删除或标为已闭环。

## 跨来源去重

同一业务变化可能同时出现在消息、会议、文档和审批中。输出一条结论，证据区列出必要来源；来源数量不能膨胀 Top 5。
