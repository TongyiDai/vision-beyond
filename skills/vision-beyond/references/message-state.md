# 消息状态判定

## 阅读状态

| 状态 | 含义 | 最低证据 |
|---|---|---|
| `confirmed` | 已确认未读 | 接口返回当前用户阅读状态，或用户提供未读事实 |
| `candidate` | 可能未读 | 位于窗口且相关，但缺少阅读状态 |
| `false` | 已读/已消费 | 明确打开、回复或用户确认已读 |
| `unknown` | 无法判断 | 权限、字段或分页不足 |

搜索到、近期发送、`@我`、群活跃都不能单独支持 `confirmed`。

## 未回状态

`confirmed` 同时要求：

1. 私聊、明确 `@我` 或正文点名用户；
2. 包含问题、请求、确认、交付、选择或截止时间；
3. 已读取同一线程或私聊窗口的后续消息；
4. 消息之后没有用户的相关回复。

`candidate` 用于请求信号存在但责任、线程或分页不完整。`false` 用于用户已经闭环或内容本身没有回复期待。`unknown` 用于身份、权限、上下文无法核验。

群里的 `@all` 只有在正文明确指定用户责任时才能进入 `confirmed`。

## 核验纪律

- 使用认证结果中的用户标识比较发送者，不用展示名比较。
- 发现用户后续发言仍需判断是否回应了原请求；旁支讨论不能自动闭环。
- 线程分页未完成时，未回状态最高为 `candidate`。
- 阅读状态与未回状态独立输出；已读消息仍可能待回复。
- 当前用户在消息发送后添加 reaction，可以作为“已经接触该消息”的正向证据，阅读状态记为 `false`；它不能证明已经理解全文。
- `DONE`、`OnIt`、`CheckMark`、`Yes` 等表情只有在请求简单、指向单一且无后续追问时，才可作为轻量回应支持 `reply_state=false`；其余情况只降低“未回”置信度。
- 没有 reaction 不构成未读或未回证据。
