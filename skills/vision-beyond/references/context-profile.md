# 工作地图与议题确认

## 目的

工作地图是排序基准，只保留用户确认的工作议题、排除项和来源偏好。身份、OKR 和近期活动提供草案证据，不能静默变成永久兴趣画像。

## 采集顺序

1. 身份：读取当前用户可见资料，记录姓名、职能/部门和租户边界。字段缺失时保留缺口。
2. OKR：获取当前周期和当前用户的 Objective、KR、进展、截止时间、对齐方向。
3. 审批与任务：查询待办、未读知会、相关未完成任务，提取仍需动作的客户、项目、交付和截止时间。
4. 近期工作：默认回看 14 天，读取用户发送的消息、会议、本人编辑/评论/打开过的文档，以及相关主题的文档更新。
5. 归并：同一项目跨来源合并为一个议题。

## 草案格式

每次生成 5–8 个候选：

```text
topic: 用户能理解的短名称
why: 对当前工作可能重要的原因
evidence: 一至两条可回溯来源
signals: OKR / 消息 / 会议 / 任务 / 审批 / 文档
search_terms: 核心实体、简称和同义词
confidence: high | medium | low
source_gap: 缺少的权限或数据域
```

至少两类来源支持时才给高置信度。单一来源可以保留，但需标为低置信度。

## 用户确认协议

接受自然语言修正，例如“保留 1、3”“合并两个客户议题”“只看我负责的”“暂时不要会议”。只保存议题名、搜索词、排除词、来源偏好、时间和时区。

后续发现的新议题放入“待确认候选”，不能自动扩张长期地图。

## 现实边界

- OKR 缺权限时，工作地图必须标为临时版本。
- 任务可能含多年旧事项，需用更新时间、截止时间和议题关系衰减。
- Drive 搜索只证明当前身份可发现对象；打开记录支持消费线索，无法普遍证明从未打开。
- 审批待办是行动状态，审批未读是消费状态，两者分别建模。
